# 柚月小手机增强

给「柚月小手机」补三个功能，不修改小手机和小白X的任何文件。设置在酒馆「扩展」页，名字是「柚月小手机增强」。

## 1. 小白X记忆
小手机里 AI 的请求（微信、朋友圈、微博、日记等）原本读不到小白X的剧情记忆。开启后每次请求都会带上。可以按 App 选择要不要带。
记忆放在手机带进来的主线正文聊天的**末尾**（正文后面、手机自己的规则前面），和小白X记忆包开头那句“以上是还留在眼前的对话，以下是脑海里的记忆”对得上。

### 1.1 手机请求的缓存点（给 Claude 缓存用）
手机的 AI 请求不经过酒馆的发送流程，所以 st-compress-cache 管不到它们。开启后，本扩展会在每次手机请求里，往“稳定内容”的结尾加一句 gproxy 认识的魔法字符串（和 st-compress-cache 用的是同一句），gproxy 会删掉它并打上缓存点。

- 最多打两个点：① 正文 + 小白X记忆的结尾；② 第一条“每次都变的内容”（微信记录、朋友圈、通话记录、短信记录等）的前一条。每次变的内容和最后的提问不打点。
- 要求：API 走 gproxy，并且那个渠道里打开了 Magic-string cache。**如果手机用的不是 gproxy，请把这个开关关掉**，否则那句魔法字符串会原样发给模型。
- 缓存时长可选 5 分钟（默认）或 1 小时（写入费用贵一倍，适合隔很久才回一条手机消息的人）。
- 手机的缓存和正文的缓存是两份：手机的开头和正文不同，第一次发手机消息会重新写入，之后连续用才会命中。
- 每次发新的正文消息，手机带的正文窗口会往后滑一格，那一次会重新写入，属于正常。

## 2. 通话智能滚动
语音 / 视频 / 电话通话时，你往上翻看消息不会再被拉回最底部；你自己发消息时仍然滚到底部。

## 3. 微信连发消息的时间
AI 一次连发很多条微信时，小手机会让时间一条条往后推。原版推得很快（按字数推进几分钟，连发短消息从第 3 条起还要额外加 1~3 分钟），一轮能跨十几分钟，中间出现好几个时间胶囊。
本功能让每条消息的间隔**只由这条消息本身决定**，像真人发消息：一点固定的反应时间 + 字数 × 每字用时，再加一点随机。
比如 2 个字约 6~10 秒，10 个字约 14~24 秒，30 个字约 35~60 秒。没有「一轮总共几分钟」的限制，条数多、消息长，时间自然就久。
设置里只有一个「时间推进幅度（百分比）」，默认 100。**方向容易搞错，记这一句：填小 = 时间走得少，填大 = 时间走得多。**
- 100：一条 30 字的消息约推进 47 秒，20 条约 16 分钟。
- 50：上面的一半（一条约 23 秒）。
- 200：上面的两倍（一条约 94 秒）。
嫌时间跳得太快就填小（例如 30~50）；想让它跳得更多才填大。设置框下面会实时算出「一条 30 字约多少秒 / 20 条约多少分钟」，不用猜。

时间胶囊（距离上一个胶囊满 3 分钟才出现新的）是小手机自带规则，本功能不改：所以就算每条只推几十秒，界面上的胶囊也大约每 3~4 分钟出现一个，这是正常的。

**如果调了没反应，先看这一条：** 小手机设置里有个「线上时间按现实时间」（只在「纯线上模式」下出现，默认是**开**）。开着的时候，微信时间按你等 AI 的**真实时间**走——AI 慢几分钟，时间就跳几分钟，本功能的百分比完全不生效。
在小手机「设置 → 纯线上模式那一块」把它关掉，改成用剧情时间，「时间推进幅度」才会生效。「检查状态」会直接告诉你现在是不是这个情况。只对新生成的消息有效。
## 4. 微信聊天自动摘要
**解决的问题：** 小手机只取每个聊天「最近 N 条」发给 AI，更早的直接丢掉，角色会越聊越忘。本功能让发给 AI 的聊天记录变成「一份摘要 + 最近的原文」。
- 每个聊天（单聊、群聊）里，AI 能看到的消息攒到「触发条数」（默认 300，语音/视频通话里说的每句话也算一条，和小手机自己的算法一致），就把最老的「压缩条数」（默认 200）交给 AI 写进摘要，留下最新的约 100 条原文。
- 摘要是**合并成一份**：每次把「旧摘要 + 新压缩的内容」重写成一份新摘要，长度基本固定（默认 1500 字左右）；越早的事越模糊，但不会直接消失。
- 摘要写成功之后，才给被压缩的消息打上小手机自带的 `hiddenFromPrompt` 标记。这些消息**在手机里照常看得到**，只是不再发给 AI；失败时什么都不改，5 分钟后自动重试。
- 摘要出现在「微信聊天记录」里该聊天标题行的下面，**手机的 AI 请求和酒馆正文都会带**。正文、小白X记忆、世界书等其他部分的结构和位置不变。
- 摘要用小手机自己的 API 生成，会产生一次较大的请求（约等于 200 条聊天的长度）。
- 「撤销全部摘要」按钮：把所有被压缩的消息恢复成普通消息，并删除摘要。
- 摘要和压缩标记存在当前酒馆聊天里（手机存储的 `chat_yp_plus_summary`）。

**酒馆正文里怎么放：** 压缩之后，该聊天在正文里是「摘要 + 所有还没被压缩的原文」（压缩完约 100 条，之后涨到 300 条左右）。小手机往正文注入时只会取「最近 N 条」且不认被压缩的标记，所以本扩展会把正文里已被压缩的那几条删掉（保留小手机原来的格式，只删开头）。删之前会先核对条数，对不上就不删（摘要和旧消息重复出现，不会丢信息），「检查状态」里会提示。

**配合小手机设置（重要）：**
- 线下的「微信单聊注入条数」「微信群聊注入条数」要**大于触发条数**，建议 400。设成 100 的话，正文里只有最近 100 条，中间的会丢（既不在摘要里，也不在正文里）。
- 线上的「单聊/群聊上下文条数」同样建议 400。
## 安装
把本文件夹里的三个文件（manifest.json、index.js、README.md）放在 GitHub 仓库的最外层，用仓库地址在酒馆「扩展 → 安装扩展」里安装。更新后刷新页面。
装好后在设置里点「检查状态」确认每项都已生效。

## 5. 手机读取的正文楼层，跟随小白X的总结进度

小手机里设置的「正文楼层数」（比如 20）原本永远取聊天最后 20 层。如果小白X已经总结到第 70 楼、后面还有 30 楼正文，手机就会漏掉第 71~80 楼：小白X的记忆里没有它们，手机的 20 层里也没有它们。

开启后，手机每次读取正文时，实际读的层数 = 「你设置的数」和「小白X还没总结（还在酒馆正文里）的楼层数」中较大的那个。小白X总结得越多，手机读的越少；小白X还没总结的楼层，手机一层都不会漏。

- 以小白X「隐藏已总结」实际隐藏到的位置为准；没开隐藏时按小白X的总结进度算。
- 小白X还没总结过时，行为和以前完全一样。
- 为防止小白X长期不总结导致越读越多，最多读 200 层。
- 手机设置页里显示的仍然是你自己填的数字。
- 「检查状态」里能看到：小白X总结到第几楼、手机现在实际读几层。

## 6. 手机请求的推理强度

柚月小手机发给酒馆后端的请求里本来没有「推理强度」（reasoning_effort）。酒馆主聊天里的推理强度设置只管主聊天，管不到手机。

这个功能在手机请求发出去之前补上 reasoning_effort（极低 / 低 / 中 / 高 / 最高，或「不设置」保持原样），酒馆后端会把它转成 Claude 的 `output_config.effort`。默认是「极低」。

- 只改手机自己的请求，酒馆主聊天的请求不动（靠手机请求特有的字段识别，并且只在手机请求进行期间才改）。
- 只对走酒馆「Claude」通道、并且是自适应思考的新模型（Claude 5 系列、Opus 4.7 及以上）生效。老模型（如 opus-4-5）不带这个参数时本来就不思考，加了反而会开启思考，所以自动跳过。
- 改变这个参数后，第一次手机请求的缓存可能要重新写入一次。
- 「检查状态」里能看到「最近一次手机请求」有没有成功加上。

## 7. 摘要管理（查看 / 修改 / 单独撤销）

扩展设置里「微信聊天自动摘要」下面有一个「管理摘要」按钮，点开后按微信窗口列出**当前打开的这个酒馆聊天**里的所有摘要：

- **查看**：每个窗口一个文本框，显示摘要全文，以及已压缩几次、最后更新时间、对应多少条已压缩的聊天。
- **修改**：直接改文本框里的文字，点「保存修改」。下一次手机请求和酒馆正文就会用新文字。不会改压缩次数，也不会动聊天消息。摘要不能保存成空的。
- **单独撤销**：「撤销这个窗口的摘要」只恢复这个窗口被压缩的消息、删掉这个窗口的摘要，别的窗口不受影响。如果恢复后原文又够触发条数，之后会自动重新压缩。

说明：
- 摘要存在当前这份酒馆聊天自己的数据里（键 `chat_yp_plus_summary`，在手机存储的 `st_virtual_phone` 下），每个微信窗口一条；换聊天、换角色卡看到的是另一批。
- 这个窗口正在生成摘要时，保存和撤销会被拒绝，等它结束再操作。
- 如果某份摘要对应的微信聊天已不存在，或这个窗口里已没有被压缩的消息，面板会标出「不会被使用」，可以直接删除。
- 手动改过的摘要，下一次自动压缩时会连同新聊天一起并入新摘要（AI 会参考你改过的文字）。

## 8. 正文里角色发起的微信，时间也按同一套算法走

角色在酒馆正文里主动发来的微信（手机叫「线下消息」），以及之后继续从正文来的回复，手机不是走微信窗口的时间算法，而是每条消息直接向它的「时间管理器」要 0~3 分钟，所以几条就过去三分钟，而且「时间推进幅度」调了也没用。

现在这个扩展也接管了这一步：同样按字数算秒，折成分钟（不足一分钟的部分按概率进位，平均下来和秒数一致），「时间推进幅度」同样生效。「检查状态」里「微信时间推进」下面多了一行「正文发起的微信」，能看到有没有生效、最近一条推进了几分钟。

限制：
- 如果正文里 AI 自己在消息里写了具体时间（例如 21:07），手机会直接用它写的时间，扩展管不到，这要靠预设让 AI 别乱写时间。
- 你自己在正文里用 `<回复xxx>` 标签发的消息，手机规定每条至少 1 分钟，扩展不改它。
- 「线上时间按现实时间」开着时，仍交回手机处理。
